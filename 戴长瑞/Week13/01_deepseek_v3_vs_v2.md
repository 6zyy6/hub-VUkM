# DeepSeek-V3 与 V2 主要改进总结

DeepSeek-V3 在继承 V2 的 MLA（多头潜在注意力）与 DeepSeekMoE 两大核心架构的基础上，对模型规模、训练效率、负载均衡策略和预测能力进行了全面升级。核心变化包括引入**无辅助损失的负载均衡策略**和业界**首创的 FP8 混合精度训练**，在性能大幅提升的同时，训练和推理成本不增反降。

## 架构升级：更大，更聪明

| 对比维度 | DeepSeek-V2 | DeepSeek-V3 | 关键变化/提升 |
| :--- | :--- | :--- | :--- |
| **总参数量 (Total)** | 236B | **671B** | 参数总量增长近 3 倍，模型容量大增 |
| **激活参数量 (Active)** | 21B（每个 token） | **37B**（每个 token） | 每次推理仅激活部分专家，运算高效 |
| **专家数量 (Experts)** | 160 个 | **256 个 + 1 个共享** | 更多专家提升了知识的“广度”和“专业化”程度 |
| **门控函数 (Gating)** | Softmax | **Sigmoid** | 允许更灵活地组合多个专家 |

## 训练与推理：更快，更省

| 对比维度 | DeepSeek-V2 | DeepSeek-V3 | 关键变化/提升 |
| :--- | :--- | :--- | :--- |
| **训练数据量** | 8.1T tokens | **14.8T tokens** | 数据量提升近一倍 |
| **训练成本 (GPU 小时)** | 未直接给出 | **~278 万 H800 小时** | 极致的成本控制 |
| **推理速度 (TPS)** | 20 TPS | **60 TPS** | 推理速度提升 3 倍 |
| **混合精度训练** | 未应用 FP8 | **FP8 混合精度** | **首创技术**，大幅降低显存和计算开销 |

## 其他关键创新

- **负载均衡**：V3 采用**无辅助损失的负载均衡策略**，不再额外增加损失函数，通过动态调整保持专家负载均衡；V2 则需要依赖辅助损失函数，会引入额外通信和计算开销。
- **预测机制**：V3 引入**多令牌预测机制（MTP）**，可一次预测多个 Token，相比 V2 的单 Token 预测，训练效率和推理能力大幅提升。
- **通信优化**：V3 使用更复杂的 **64 路专家并行 + 16 路流水线并行**，优化后的并行策略充分发挥了超大规模 MoE 的优势，这也是总参数大增而训练成本基本不变的原因之一。

## 性能提升

- 在编程水平、数学推理等多个维度上显著超越 V2

> **总结**：DeepSeek-V3 并非简单扩容，而是一次在底层技术、工程算法和系统架构上的全方位创新，在显著提升模型性能的同时，保持了甚至更高的效率。
