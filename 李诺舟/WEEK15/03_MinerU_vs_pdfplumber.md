# 作业 2：MinerU 论文与使用总结，以及和 pdfplumber 的效果差异

## 1. MinerU 是什么

结合课程资料和官方文档，MinerU 可以理解成一套面向 LLM / RAG / Agent 场景的文档解析引擎。它的目标不是“尽量把 PDF 文本抠出来”，而是把复杂文档转成更适合下游模型使用的结构化结果，比如 Markdown、JSON、中间布局结果。

核心特点有四类：

1. 版面理解：能处理单栏、多栏、复杂排版，并按阅读顺序输出。
2. 结构恢复：保留标题、段落、列表、表格、图片、脚注等结构。
3. 多模态抽取：支持图片、表格、公式，并把公式转成 LaTeX、表格转成 HTML。
4. 工程化能力：支持 CLI、FastAPI、WebUI、Router、多 GPU、多服务部署。

## 2. MinerU 怎么用

### 本地命令行

官方最直接的方式：

```bash
mineru -p <input_path> -o <output_path>
```

如果设备不满足高配加速条件，也可以走纯 CPU `pipeline` 后端。

### 服务化部署

官方也支持直接启动 API：

```bash
mineru-api --host 0.0.0.0 --port 8000
```

然后可通过异步任务接口 `POST /tasks` 或同步接口 `POST /file_parse` 使用。

### 为什么适合 RAG

因为它输出的不只是纯文本，而是更接近“文档语义结构”的结果。对 RAG 来说，这意味着 chunk 切分、表格保留、图片定位、页码追溯都会更自然。

## 3. 论文和官方资料能看出什么

从 MinerU 系列论文和官方说明可以看出，它强调的是“高分辨率文档解析”和“复杂布局恢复”，而不是传统 OCR 或文本抽取库那种单点能力。

我总结三个关键点：

1. 它把文档解析视为一个完整管线，而不是单一文本提取问题。
2. 它重点优化复杂文档，如多栏论文、图表混排、扫描件、公式和跨页表格。
3. 它不仅追求准确率，也在做工程层面的可部署性，比如异步任务、Router、纯 CPU / GPU、多服务路由。

## 4. MinerU 和 pdfplumber 的差异

### 4.1 原理差异

`pdfplumber` 更像 PDF 文本层抽取工具。它擅长读取文字坐标、字符、线条、页面对象，适合做：

- 纯文本 PDF 抽取
- 简单规则表格抽取
- 轻量脚本处理

但它本身不负责“重建文档结构语义”。

MinerU 则更像“文档理解系统”。它会做版面分析、结构识别、OCR 兜底、公式/表格恢复，再输出结构化内容。

### 4.2 效果差异

如果文档是简单、规整、纯文本 PDF：

- `pdfplumber` 往往已经够用，速度快，依赖轻。
- MinerU 也能做，但有点“大材小用”。

如果文档是复杂 PDF：

- 多栏排版
- 图文混排
- 表格跨行跨列
- 含公式
- 扫描件或乱码 PDF

这时 MinerU 通常明显更好，因为它会尝试恢复阅读顺序和结构，而 `pdfplumber` 常见问题是：

1. 文字顺序乱。
2. 表格被拍平成碎片文本。
3. 图片和文字关系丢失。
4. 公式无法得到良好表达。
5. 扫描版 PDF 基本无能为力，除非额外接 OCR。

### 4.3 对 RAG 的影响

对 RAG 来说，最重要的不是“能不能抽出字符”，而是“抽出来的结果能不能直接拿去切 chunk 和检索”。

在这一点上：

- `pdfplumber` 输出更原始，需要自己再做很多清洗和重排。
- MinerU 输出更接近 LLM-ready 数据，后续接向量检索和多模态问答更顺。

## 5. 一句话结论

如果目标只是轻量文本提取，`pdfplumber` 更简单直接；如果目标是复杂文档解析并服务于 RAG / Agent，MinerU 更合适。

## 6. 本次作业里的结论

结合 `05-multimodal-rag-chatbot` 的需求，我认为生产版本应该优先选 MinerU，而不是只靠 `pdfplumber`：

1. 这个项目要处理图文混排 PDF。
2. 最终要做多模态检索和问答。
3. 需要保留图片、表格、公式和来源定位。

因此，`pdfplumber` 适合作为本地开发兜底方案；MinerU 才是更符合最终架构目标的主解析器。
