# 第十五周作业需求说明

## 1. 目标

基于 `05-multimodal-rag-chatbot` 的原始思路，交付一份可以直接演示的初版工程，重点是把原 README 里已经定义过的接口落成代码，并把后续可扩展的多模态 RAG 架构先搭出来。

本次交付聚焦三件事：

1. 保留并实现现有接口：`POST /upload/document`、`POST /chat`。
2. 把文档上传、解析、入库、检索、回答这条链路拆成清晰模块。
3. 补上测试逻辑和作业说明，保证提交可读、可扩展、可验证。

## 2. 需求拆解

### 2.1 文档上传接口

- 接口：`POST /upload/document`
- 输入：`knowledge_base_id`、上传文件 `file`
- 行为：
  - 将原始文件保存到本地目录
  - 生成文档元数据
  - 将文档放入待处理队列
  - 异步触发解析任务
- 输出：`document_id`、`task_id`、`status`

### 2.2 多模态问答接口

- 接口：`POST /chat`
- 输入：`knowledge_base_id`、`question`、可选 `top_k`
- 行为：
  - 从指定知识库取已处理 chunk
  - 执行检索
  - 组合命中文本、图片引用和来源信息
  - 生成当前版本的草稿回答
- 输出：`answer`、`sources`

### 2.3 解析与索引流程

- 当前初版支持：`.txt`、`.md`、`.pdf`
- `.txt/.md`：本地直接切块
- `.pdf`：通过 `pdfplumber` 做文本抽取，作为本地开发兜底解析方案
- 后续替换位：MinerU / DeepSeek-OCR / CLIP / BGE / Milvus / Qwen-VL

## 3. 本次初版范围

### 已完成范围

- FastAPI 服务骨架
- 上传接口
- 问答接口
- 本地文件存储
- 内存版知识库存储

## 4. 设计原则

- 先把接口契约稳定下来，再替换底层实现。
- 先写可测试的本地版，再接入 GPU 和外部模型服务。
- 先把职责拆开，避免把上传、解析、检索、回答耦合在一个脚本里。
