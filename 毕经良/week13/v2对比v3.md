### 一、架构改进

#### 1. **无辅助损失（Auxiliary-Loss-Free）的负载均衡策略**

- **V2**：依赖辅助损失（auxiliary loss）来鼓励专家负载均衡，但过大的辅助损失会损害模型性能。

- **V3**：引入动态偏置项（bias term）调整路由，无需辅助损失即可实现负载均衡，同时保留极轻量的序列级均衡损失（`α=0.0001`）防止单序列极端不均。实验表明该方法在多个基准上优于纯辅助损失方法。

#### 2. **多 Token 预测（Multi-Token Prediction, MTP）**

- **V2**：仅预测下一个 token。

- **V3**：在训练时额外预测多个未来 token（深度 D=1，即额外预测一个 token），使用顺序模块保持因果链。该目标增强了训练信号，提升了模型性能，且推理时可丢弃 MTP 模块。同时，MTP 模块可复用于推测解码（speculative decoding）以加速生成（实测 TPS 提升 1.8 倍，接受率达 85%~90%）。

#### 3. **专家路由与负载均衡细化**

- **V3** 使用 sigmoid 计算亲和度，并对选中的 top-K 专家做归一化；采用节点限制路由（Node-Limited Routing），每个 token 最多发往 4 个节点，减少跨节点通信。全程无 token 丢弃（no token-dropping）。

### 二、训练效率与基础设施优化

#### 1. **FP8 混合精度训练**

- **V2**：主要使用 BF16 训练。

- **V3**：首次在超大规模模型（671B）上成功应用 FP8 训练，提出细粒度量化（1×128 逐 tile 激活量化 + 128×128 逐块权重量化）、高精度累加（CUDA Cores 每 128 个元素进行 FP32 累加）和在线量化等技术，相对 BF16 的误差低于 0.25%，显著降低显存和通信开销。

#### 2. **DualPipe 流水线并行算法**

- **V3** 提出 DualPipe，实现双向流水线调度，大幅减少流水线气泡（pipeline bubbles），并通过计算-通信重叠隐藏了大部分跨节点 all-to-all 通信开销。相比 1F1B 和 ZB1P 方法，气泡更小，显存增加可控。

#### 3. **跨节点 All-to-All 通信优化**

- 利用 warp specialization 技术，将 20 个 SM 划分为 10 个通信通道，动态分配 IB 和 NVLink 的传输任务，实现 IB 和 NVLink 带宽的充分利用。每个 token 平均每节点选择 3.2 个专家，支持最多 13 个专家（4 节点 × 3.2）而不增加通信成本。

#### 4. **极致内存节省**

- 重计算 RMSNorm 和 MLA up-projection；EMA 参数存储在 CPU 并异步更新；MTP 模块与主模型共享 embedding 和输出头的物理参数，减少冗余。

### 三、后训练与知识蒸馏

#### 1. **从 DeepSeek-R1 蒸馏推理能力**

- **V2**：依赖常规 SFT 和 RL。

- **V3**：利用 R1 的长链推理（long CoT）数据，通过系统提示引导模型生成包含反思（reflection）和验证（verification）的响应，再经过 RL 和拒绝采样（rejection sampling）提炼为高质量 SFT 数据。显著提升了数学（如 MATH-500 达 78.3%）和代码（如 LiveCodeBench）性能。

#### 2. **自奖励（Self-Rewarding）机制**

- 在无外部反馈的通用场景中，利用 V3 自身的投票评估结果作为奖励信号（constitutional AI），提升主观任务表现。

### 四、数据与上下文

#### 1. **更大、更优的预训练数据**

- 训练 token 从 V2 的约 8.1T 提升到 **14.8T**，增加了数学、编程和多语言（除中英文外）比例。采用文档级 FIM（Fill-in-Middle）策略（比例 0.1），提升代码理解能力。

#### 2. **长上下文扩展**

- 两阶段 YaRN 扩展：4K → 32K → **128K**，在 NIAH 测试中 128K 内表现稳定。

#### 3. **Tokenizer 优化**

- 词汇量扩展至 **128K**，引入标点与换行符组合 token，并通过随机拆分缓解 token 边界偏差（token boundary bias）。
