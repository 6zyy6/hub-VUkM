# 多模态 RAG Chatbot 需求说明

## 背景

课程材料中已有文档解析、Search RAG、DeepResearch 的基础示例。本作业将 `05-multimodal-rag-chatbot` 定义为一个面向解析后文档的问答服务：上游可以来自 MinerU、pdfplumber 或人工整理的 Markdown，下游通过 Chat API 返回带引用的回答。

## 用户故事

1. 作为知识库维护者，我可以提交文档标题、来源路径、正文 Markdown 和图片引用，让系统切分并索引。
2. 作为提问用户，我可以输入问题，系统检索最相关片段并返回答案、引用、检索片段和是否用到图片。
3. 作为接口调用方，我可以通过固定 API 检查健康状态、写入文档、检索片段、发起聊天。
4. 作为开发者，我可以用离线的假 embedding 与模板回答跑通测试，后续再替换为真实 embedding、rerank 和 LLM。

## 功能范围

- 支持 Markdown 文档按标题和长度切分。
- 支持提取 Markdown 图片语法 `![alt](path)`，保留为 chunk 的多模态元数据。
- 支持内存向量检索，默认使用确定性的词袋相似度，便于测试。
- 支持回答中返回引用列表，引用包含 `source`、`heading`、`chunk_id`、`score`。
- 支持 FastAPI 适配层，接口保持稳定，便于后续替换底层实现。

## 非目标

- 本阶段不接真实大模型，不处理用户鉴权，不做持久化数据库。
- 本阶段不直接解析 PDF；PDF 解析由 MinerU/pdfplumber 等上游工具完成。
- 本阶段不做复杂前端，只提供后端接口和可测试服务层。

## 成功标准

- `pytest` 全部通过。
- 文档清楚说明需求、架构、测试逻辑和后续演进点。
- 代码结构能自然替换 embedding、rerank、LLM 与持久化存储。
